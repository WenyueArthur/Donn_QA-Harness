# 一页上手指南

本页是未来产品的使用规格。当前交付包只有方案，下面的产品命令尚未实现。
交付文件自检请阅读 [README](README.md)，不要把它当作产品演示。

## 首次使用

管理员准备软件和依赖后，先体验离线实验：

```bash
python -m qa_flow demo
```

实验使用合成需求、数据和平台，不需要真实账号或网络。
按提示处理业务问题、观察缺陷与实验修复，再导出报告。
屏幕应始终说明这是合成实验，不代表真实业务或生产通过。

## 日常只需四类操作

| 想做什么 | 使用什么 |
|---|---|
| 开始一个需求 | `python -m qa_flow start --source "./需求.md"` |
| 继续未完成工作 | `python -m qa_flow resume` |
| 查看并处理业务确认 | `python -m qa_flow review` |
| 查看或交付 | `python -m qa_flow status`；`python -m qa_flow export --output "./交付"` |

开始前核对屏幕中的需求名称、来源和环境。
存在多个任务时按业务名称选择，系统不能默认操作另一项需求。
无需学习内部阶段编号，也不需要生成命令 ID 或填写 JSON。

## 遇到待确认

1. 阅读具体问题、原文依据和受影响范围。
2. 在自己有权决定的范围内回答或选择选项。
3. 将需要产品、研发或原生审批的问题转交对应责任人。
4. 使用“继续”执行仍有效且获准的下一步。

系统应复用同一有效范围的答复，不反复提问。
“全部同意”不能自动批准新目标、过期内容或他人的权限。

## 遇到错误或中断

1. 查看当前结论、失败原因和已有结果。
2. 按提示修正具体业务输入，或转交管理员补充能力。
3. 使用“继续”，由系统恢复检查点并核对未知结果。
4. 查看新结果，确认失败或未知没有被隐藏。

关闭终端后，已提交工作应保留。
操作可能已经成功时，系统先查询核对，不直接重复建单或上传。
不需要通过改 JSON、查源码或关闭门禁来继续。

## 交付前

1. 查看报告中的通过、失败、未执行和未验证范围。
2. 导出本地报告，检查返回路径可以打开。
3. 需要远端归档时，另行审阅归档目标和写入计划。

本地导出不会自动写飞书、修改缺陷或发布系统。
缺少真实配置时，查看管理员处理项，不在终端粘贴明文密钥。

详细的行为边界见 [设计方案 §11](01-rebuild-design.md#11-易用性首次引导与-cli)。
