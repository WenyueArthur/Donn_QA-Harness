# 新项目重构交接包

本包是实施与验收规格，不是已经实现的 QA 产品。
采用 Python 命令行、本地 SQLite 和本地证据文件。
日常操作按四类任务组织：开始、继续、待确认、查看/交付。

## 按角色阅读

| 角色 | 先读什么 |
|---|---|
| 重构开发者 | [设计方案](01-rebuild-design.md)，从 M0 冻结基线开始 |
| 验收负责人 | [测试方案](02-validation-plan.md)，先写独立验收 |
| 产品与项目负责人 | 设计方案 §11 的任务入口、角色和确认方式 |
| 未来使用者 | [一页上手指南](QUICKSTART.md)，无需阅读内部实现规格 |

方案包含 60 项需求和 144 个验收场景。
其中 8 项需求专门约束易用性，原有可靠性要求继续保留。
这是规格覆盖数量，不是新系统已经通过的测试数量。

## 两份主要方案

1. 阅读 [QA 全流程重构设计方案](01-rebuild-design.md)。
2. 阅读 [QA 全流程重构测试与验收方案](02-validation-plan.md)。

设计明确任务入口、首次引导、管理员配置、自动续做、集中确认和错误恢复。
测试同时检验底层正确性与未参与开发者能否独立完成任务。

## 当前可以执行的检查

在本目录执行：

```bash
python3 check_handoff.py
python3 check_handoff.py --negative-selfcheck
```

仍可访问原仓库时，可额外核对关键来源：

```bash
python3 check_handoff.py --source-root /Users/donnie/PycharmProjects/qa-skills
```

检查器不调用模型、不连接业务服务、不写外部平台。
其中的数学与新人门槛检查均针对合成规格，不代表真人测试已经通过。

## 新项目实施顺序

1. 将本包放入新项目文档目录。
2. 指定新项目根，保持旧仓库、历史产物和安装副本只读。
3. 完成 M0，冻结完整旧规则与正反样本。
4. 先写验收，按 M1 至 M8 实现核心与任务入口。
5. 先用无账号离线实验验证，再接真实测试平台和模型。
6. 使用未参与开发的人员完成规定新人任务。
7. 最后核验获得明确授权的生产只读范围。

易用性从 M1 开始，M3/M4 验证日常入口，不能到最后才补指南。
5 名新人各 5 项任务是拟定门槛，尚未实测；不能据此宣传上手时间。

## 新会话启动说明

> 根据两份方案、需求与场景清单实施。
> 先完成 M0，不改旧仓库、历史产物、安装副本或外部系统。
> 日常用户不需要手填内部 ID、修订号或 JSON。
> 任务入口必须调用同一套校验和授权，不能省略可靠性检查。
> 每批报告真实通过、失败、受阻和未验证范围。
> 不把文档自检、模拟结果或开发者演示当新人实测通过。

新会话仍需读取所在项目的实际指令与权限。

## 文件维护

只维护当前这一套方案，不保留旧版、备份版或并列参数入口。
后续修订需同步需求、场景、两份方案、上手指南和摘要。
保留实际测试失败记录，不通过删除失败样本缩小验收。
文件摘要只能发现内容变化，不能认证决定人或防御同一 OS 用户恶意篡改。
